# Code of Conduct

## Our standard

Be respectful, constructive, and specific. Debate technical ideas without attacking people. Assume good faith while still taking security, privacy, authorization, accessibility, and user safety seriously.

Unacceptable behavior includes harassment, threats, discriminatory abuse, doxxing, deliberately publishing secrets, or using project spaces to facilitate unlawful access to third-party systems or media.

## Project spaces

This applies to Melodex issues, pull requests, discussions, documentation contributions, registry proposals, code review, and other project-managed community spaces.

Technical disagreement is welcome. Personal attacks are not.

## Security and private information

Do not publish credentials, bearer tokens, private keys, cookies, signed media URLs, or another person's private information in a public issue or pull request.

Security-sensitive reports should follow [SECURITY.md](SECURITY.md).

## Enforcement

Project maintainers may edit, hide, reject, lock, or remove contributions or participation that violate this standard.

Enforcement decisions should be proportionate to the behavior and focused on keeping project spaces useful and safe.
