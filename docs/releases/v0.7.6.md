# Melodex v0.7.6

## Provider and playback reliability

This patch release focuses on connected-source reliability and the everyday Search experience.

### Cleaner Search sources

- Hides older **Radio Browser Example** and **LibriVox Example** entries when the production bundled providers are installed.
- Keeps those examples available for development/reference use without querying them in **All sources**.
- Keeps **Openverse Audio Example** out of normal listener Search because it is a reference integration rather than a production bundled source.

### LibriVox 0.1.5

- Fixes playback when Internet Archive redirects audiobook media to regional CDN hosts such as `*.ca.archive.org`.
- Expands the allowed Archive media host pattern to `*.archive.org` while keeping Melodex's secure playback host validation in place.

### Internet Archive Audio 0.1.2

- Applies the same regional Archive CDN redirect fix to Internet Archive Audio.
- Retains the lightweight search behaviour introduced in 0.1.1, where full item/file metadata is resolved only when a result is opened or played.

### Playback gateway improvements

- Melodex's playback gateway now sends a descriptive Melodex User-Agent when a provider does not supply one.
- Provider-specific User-Agent headers are preserved.
- This fixes Wikimedia Commons audio returning HTTP 403 through the real desktop playback path.

## Stronger live provider verification

The live provider audit now probes media through the same secure playback gateway used by the desktop player instead of only checking raw upstream bytes.

The final gateway-level audit passed for:

- ccMixter
- Wikimedia Commons Audio
- Radio Browser
- Internet Archive Audio
- SomaFM
- LibriVox
- NicheDB Radio
- Openverse Audio reference provider

This means redirect validation, allowed-host rules, provider headers and gateway behaviour are now exercised by the live provider checks.
