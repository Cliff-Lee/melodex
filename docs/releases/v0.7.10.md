# Melodex v0.7.10

## NAS resilience and beta diagnostics

v0.7.10 hardens the v0.7.9 Elastic Library Engine for real network-storage use.

Campaign 10 proved that Melodex's library architecture can scale synthetically to very large collections. Campaign 11 focuses on a different problem: what happens when the library lives on SMB/NFS/NAS storage that is slow, intermittent, temporarily unavailable, or drops out during a scan.

### Bounded retry for transient NAS failures

Root checks, directory enumeration and audio-file stat operations now tolerate brief filesystem hiccups with a deliberately small retry budget:

- first retry after 50 ms;
- second retry after 150 ms;
- persistent failures are then treated as real storage failures rather than retried indefinitely.

Recovered I/O retries are counted in scan metrics for diagnostics.

The budget is intentionally conservative. Melodex should absorb momentary SMB/NFS glitches without hammering or masking a genuinely unhealthy share.

### Fail-safe catalog preservation

If a NAS is unavailable or a scan becomes incomplete partway through traversal:

- the partial network view is not published;
- cached tracks are not interpreted as deleted;
- the last committed SQLite catalog remains authoritative;
- the existing library remains available to browse while the storage problem is resolved.

This also covers a network share disappearing after traversal has already started.

### Less unnecessary NAS traffic

Production traversal no longer performs audio-style stat work for non-audio sidecars such as artwork and text files.

Adaptive storage concurrency from v0.7.9 remains in place. Under injected high-latency storage, the qualification requires Melodex to move to the conservative high-latency profile with two metadata workers and no more than four metadata reads in flight.

### Permanent NAS fault qualification

v0.7.10 adds a dedicated **NAS fault qualification** CI gate.

The qualification wraps the real isolated Melodex scanner with deterministic test-only filesystem faults and verifies:

- high-latency storage reduces scanner concurrency;
- intermittent directory failures recover inside the bounded retry budget;
- intermittent stat failures recover safely;
- a whole share disappearing mid-scan preserves the committed library;
- cached-library reads remain available during deliberately slow rescans;
- a worker blocked in very slow metadata I/O remains hard-cancellable;
- the normal no-fault scan path still behaves correctly.

The fault injector exists only under the engineering qualification tools. Packaged Melodex has no fault-injection switches.

### Clearer NAS fallback UX

Network-storage fallback is now explicit instead of looking like an ordinary successful scan.

If a configured location is unavailable, My Music can report:

> **Library kept available**  
> Music location unavailable  
> Showing your last indexed library. No cached tracks were removed.

If traversal begins but cannot complete reliably, Melodex explains that the last indexed library is being shown and that no partial scan was applied.

Degraded-storage and scanner-error messages remain visible rather than disappearing behind a short-lived success notification.

### Redacted beta diagnostics

**Sources & plugins → Export redacted diagnostics…** is now available without enabling Power tools.

The diagnostics schema is now **0.2** and can include:

- Melodex and platform version;
- packaged/source build state;
- aggregate catalog/index counts;
- scan phase and elapsed time;
- files/tracks/directories processed;
- unavailable/incomplete root counts;
- transient I/O retry count;
- storage latency profile;
- metadata concurrency;
- responsiveness and background-scheduler summaries.

The export deliberately excludes:

- library roots and mount paths;
- NAS/share names;
- directory and file names;
- credentials;
- stream/playback URLs;
- request headers/cookies;
- raw filesystem exception messages.

Only a coarse error type is retained. Testers should still review the JSON before sharing it.

## Validation

The Campaign 11 release head passed:

- Python 3.11 test suite;
- Python 3.12 test suite;
- dedicated NAS fault qualification;
- 12.7k Elastic Library qualification;
- 12.7k large-library baseline;
- 12.7k Fluid mixed-workload soak;
- Fluid Melodex responsiveness/release gates;
- startup baseline;
- macOS Apple Silicon desktop build;
- macOS Intel desktop build;
- Windows x64 desktop build;
- Linux package build;
- Ubuntu 22.04, 24.04 and 26.04 smoke tests;
- Debian smoke test.

These tests exercise deterministic local/fault-injected storage conditions. They do **not** claim that every real SMB/NFS/NAS device will behave identically. Real-world beta testing remains important, particularly with large FLAC collections and consumer NAS hardware.

## Relationship to v0.7.9

v0.7.9 remains the major scaling release: bounded streaming discovery, incremental SQLite persistence, directory reuse, resumable scans and synthetic qualification through one million tracks.

v0.7.10 builds on that engine by making network-storage failure modes safer, more observable and easier for users/testers to understand.
