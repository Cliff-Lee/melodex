# Melodex v0.7.12

## Architecture underneath, visual polish on top

v0.7.12 combines two large internal campaigns into one release.

Campaign 12 reduced how much feature ownership lives in the main window and
moved major areas behind clearer boundaries. Campaign 13 then rebuilt the visual
experience on top of that architecture and added explicit performance and visual
quality gates.

The result is a release that should feel more coherent to use while also being
easier to continue developing safely.

## A cleaner internal architecture

The desktop app now has clearer ownership around several major areas:

- local-library scan status and scan coordination;
- navigation and lazy page lifecycle;
- source and plugin policy;
- Sources;
- Journeys;
- playback and Now Playing.

Playback authority remains with the player. Feature surfaces request semantic
actions instead of taking direct ownership of playback internals.

MainWindow is now substantially less responsible for feature-specific state and
orchestration, which reduces the risk of unrelated changes breaking each other.

## One lyrics system

Lyrics now use one canonical state for both:

- the practical Now Playing lyrics reader; and
- the immersive Lyric Flow visual.

The reader keeps search, source switching, refresh, editing/import workflows,
click-to-seek for synchronized lines and readable typography.

Lyric Flow reuses the same data and timing rather than maintaining a second
lyrics implementation.

## Lyric Flow

The fullscreen/visual presentation now has:

- large active lyrics with restrained blue-white glow;
- faded previous and next context;
- smooth vertical transitions;
- subtle music-linked breathing;
- artwork-derived dark atmosphere;
- synchronized and untimed fallbacks;
- bounded artwork caching so large displays do not create unnecessary work.

## Constellation 2.0

Constellation is now an explorable music neighbourhood rather than a fixed
hub-and-spoke diagram.

- stronger relationships sit closer to the current track;
- path strength has semantic meaning;
- hover reveals artwork for recognition;
- click holds a selection;
- activation still routes through semantic playback actions;
- the current track uses the reusable Track Sigil identity.

The design principle is:

**Stars for overview. Artwork for recognition. Paths for meaning.**

## Profile Pulse and Sonic Weather

Profile Pulse replaces the older radar-like presentation with a deterministic,
music-shaped radial portrait. The recording keeps the same underlying identity
while playback adds restrained breathing and glow.

Sonic Weather is now an abstract atmospheric field rather than a literal weather
icon. Mist, haze, pressure fronts and sparse particles respond to cached musical
character without introducing a live FFT loop.

## Memory Atlas

Listening history now has explicit visual semantics:

- left to right = chronological time;
- height = average time of day;
- colour reinforces daypart;
- size = play count;
- width = the span of the grouped listening period;
- the connecting trail = what was heard next.

The static part of the atlas is cached, so even dense histories remain cheap to
repaint while hover/selection stays interactive.

## Track Sigil and Visuals organization

Track Sigil is now a reusable recording identity element instead of a standalone
visualizer.

The Visuals selector is organized by purpose:

### Watch

- Profile Pulse
- Lyric Flow
- Sonic Weather
- Minimal

### Explore

- Constellation
- Memory Atlas
- Musical Journey

Installed personal visualizer recipes appear separately.

Album World remains available internally for compatibility, but was removed from
the public Watch list after the final visual review found it did not meet the same
quality bar as the redesigned scenes.

## Performance safeguards

Visual rendering now has explicit budgets for:

- frame cadence;
- detail samples;
- particle count;
- glow passes;
- artwork cache resolution;
- paint time.

Auto quality only reduces after sustained slow paints, ignores cold-start cache
spikes, and recovers with hysteresis so the UI does not oscillate between
quality levels.

Representative CI p95 paint times from the final qualification were approximately:

| Scene | Auto p95 | High p95 |
| --- | ---: | ---: |
| Lyric Flow | 8 ms | 15 ms |
| Memory Atlas | 6 ms | 12 ms |
| Constellation | 15 ms | 20 ms |
| Profile Pulse | 15 ms | 28 ms |
| Sonic Weather | 13 ms | 25 ms |
| Musical Journey | 8 ms | 15 ms |
| Minimal | 8 ms | 15 ms |

## Visual QA

v0.7.12 adds deterministic visual capture tooling so the redesigned scenes can be
reviewed as actual rendered screens rather than only as code.

The final QA pass caught and fixed issues including:

- light/default Qt styling leaking into the Visuals shell;
- polygonal Profile Pulse contours;
- stripe-like Sonic Weather composition;
- an unrealistic Constellation test fixture;
- clipped Memory Atlas labels;
- noisy arbitrary Memory Atlas colours;
- a weak Album World public presentation.

The acceptance rule was simple: a flagship visual was not considered finished
until its rendered screenshot was suitable for public-facing product material.
