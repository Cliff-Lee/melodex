# Melodex v0.7.17 — P13 tester release

**Status:** prerelease candidate for controlled testing (`v0.7.17-rc.1`).

This build tests the P13 player-first startup and source-import changes. It is
available for tester feedback while healthy-NAS playback, physical audio output,
offline/reconnect behavior, and packaged startup are qualified on real devices.
The diagnostics playback event is a playback-position proxy; it does not confirm
that sound reached speakers or headphones.

## What to test

1. Start from a new install with no library. Confirm the first-run screen opens and
   **Choose Music Folder**, **Choose Audio Files**, and drag-and-drop are available.
2. Add a local music folder. Try **Play Something** as soon as tracks appear, while
   the status still indicates that indexing is continuing.
3. Add a mounted NAS folder. Try playing an early result before discovery completes.
   Also try a slow or temporarily unavailable subfolder and confirm the rest of the
   app remains responsive.
4. Reopen the app with a previously indexed library, then test with the NAS asleep,
   offline, and reconnected. Cached content should render before source refresh.
5. Try pausing, seeking, skipping, queue restore, and continuing from the saved
   position. Report any playback interruption or incorrect unavailable status.

## Send back results

In Melodex, open **Sources → Export redacted diagnostics…** and attach the JSON
export with the report. It contains event names, elapsed times, and numeric attempt
IDs; it omits paths, filenames, tags, URLs, and provider settings. Include:

- operating system and whether this was a clean install or upgrade;
- source type (local or NAS), approximate track count, and whether the NAS was warm;
- what you clicked and whether audio was actually audible;
- any freeze, error, missing track, or unexpected delay.

For a journey-specific threshold check, run
`python desktop/tools/check_first_music_qualification.py <export.json> --journey
local` (or `nas`, `warm`, or `offline`). This checks the exported timeline; it does
not replace reporting whether sound was audible.

## Known qualification limits

- The automated discovery benchmark measures filename discovery and scan completion,
  not end-to-end audible audio.
- The normal desktop test suite and platform packaging jobs must pass on the tagged
  candidate before its artifacts are distributed.
- A physical NAS with healthy, slow, stalled, disconnected, and reconnected paths is
  required to close the remaining network-storage qualification.
- Do not use this prerelease as evidence that the complete P13 campaign has passed.
